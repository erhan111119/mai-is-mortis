# 人格切换（评分触发）

给麦麦加一套「情绪积累 → 临时换人格 → 到点自动恢复」的机制。默认配置的效果：

- 有人骂麦麦 → **嘴臭人格**加分；有人夸麦麦 → **撒娇人格**加分；
- 某个人格的分数顶到阈值 → 立刻切过去，**其他人格分数清零**；
- 该人格维持若干分钟后**自动切回原人格**；
- 分数随时间衰减：最后一次加分后的宽限期内不掉，之后按配置速度往下掉。

人格的设定文本、触发词、权重、阈值、维持时长、衰减速度、模型判定条件全部在 WebUI 里可改，不用碰代码。

## 它怎么改变麦麦的语气

插件**不改写宿主的 `bot_config.toml`**。它只在「这一次发给模型的请求」里做替换：

1. `chat.receive.after_process`：每条入站消息按触发规则给对应人格加分，并判断要不要切换；
2. `maisaka.replyer.before_model_request`：临时人格生效时，把系统提示里的
   `{identity}`（人格设定）与 `{reply_style}`（说话风格）换成该人格的版本；
3. `maisaka.planner.before_request`：可选地同步改写规划器的行为风格（`{behavior_style}`）；
4. `maisaka.replyer.before_request`：把该人格的「额外要求」并进本次回复要求。

原人格文本是从宿主配置里读出来的（`personality.personality` / `reply_style` / `behavior_style`），
在提示词里定位到同一段文字后替换。因此：

- 临时人格到期后不需要「恢复」动作，下一次请求读到的仍然是配置里的原文；
- 你在 WebUI 里改人设会立刻反映到下一次回复；
- 不同会话（群 / 私聊）各记一套分数，一个群把麦麦骂急眼了，别的群不受影响。

## 安装

把整个 `persona-switcher` 目录放进 MaiBot 的 `plugins/` 下即可。宿主的插件目录监听会热加载它，日志里能看到：

```
插件 local.persona-switcher v1.0.0 加载成功
人格切换插件已加载：人格=嘴臭人格、撒娇人格；衰减 1.5 分/分钟（宽限 1.5 分钟）
```

之后在 WebUI 的插件配置页里就能看到「人格列表」表格，逐项调参。

## 配置说明

### 基础设置

| 字段 | 说明 |
| --- | --- |
| 启用插件 | 关掉后不再计分、不再切换，麦麦始终用原人格 |

### 计分与衰减

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| 每分钟衰减 | 1.5 | 宽限期结束后，每分钟掉多少分，掉到 0 为止 |
| 衰减宽限分钟 | 1.5 | 最后一次加分后的免衰减时间。宽限期内连续触发才能把分数堆上去 |
| 分数上限 | 60 | 单个人格分数上限，避免慢慢攒着、一触发就爆表；0 表示不限 |
| 最多会话数 | 200 | 最多记住多少个会话的分数，超出后淘汰最久未用的 |

### 切换行为

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| 切换时清空分数 | 开 | 切换时把所有人格（含刚切过去的这个）分数清零，避免到点后又立刻被同一批话顶起来 |
| 生效期间继续计分 | 关 | 默认生效期间暂停计分，让临时人格老老实实待够时间 |
| 同步改写规划器 | 开 | 让人格配置里的「规划行为风格」也生效，影响「要不要回、怎么回」 |
| 落盘间隔秒 | 20 | 分数状态写盘的最小间隔，写盘是为了重启后分数和剩余时间还在 |
| 记录加分日志 | 开 | 每次加分写一条 INFO 日志，调阈值时对着日志看最直观 |
| 记录入站消息日志 | 开 | 每条入站消息写一条 DEBUG 日志（会话、长度、是否 @）。排查「插件到底看没看到消息」时用得上 |

### 人格列表（表格）

每一行是一个可切换的人格：

| 字段 | 说明 |
| --- | --- |
| 人格 ID / 人格名称 | ID 唯一，用于日志与 `/人格 切换`；名称用于展示 |
| 切换阈值 | 分数加到这么多就切过去；填 0 表示这个人格不参与自动切换（只想手动用） |
| 维持分钟 | 切过去后维持多久，到点自动切回原人格 |
| 人格设定 | 替换 `personality.personality`。建议写清「这是个什么状态」+ 语气边界 |
| 规划行为风格 | 替换 `personality.behavior_style`，留空表示规划阶段保持原样 |
| 说话风格 | 替换 `personality.reply_style`，留空表示说话风格保持原样 |
| 额外要求 | 追加到本次回复要求里，用来强调「这次必须按临时人格说」 |
| 单条消息加分上限 | 一条消息同时命中多条规则时的上限，0 表示不限 |
| 人格冷却秒数 | 这个人格整体的加分冷却：冷却期内换规则也不加分 |
| 模型判定条件 / 加分 | 交给模型判断的软性条件（如「对方在挑衅」），留空不参与 |
| 触发规则 | 下面那张表 |

触发规则（每个人格一张表）：

| 字段 | 说明 |
| --- | --- |
| 触发内容 | 一行一条。关键词模式按「包含」匹配；正则模式按 `re.search` 匹配 |
| 加分 | 命中一次加多少分 |
| 匹配方式 | keyword（列举词）/ regex（写正则，如 `(?:你\|真)菜`） |
| 需要 @ 麦麦 | 开启后只有 @ 了麦麦的消息才算命中，避免群友互聊也加分 |
| 冷却秒数 | 同一条规则的加分冷却，防止有人刷屏瞬间顶满 |

### 模型判定（可选，默认关闭）

关键词覆盖不到「阴阳怪气」这类软性条件，打开这一节后会每隔一段时间把最近的对话交给模型判断一次：

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| 启用模型判定 | 关 | 打开后会消耗 token |
| 模型任务 | utils | 用 `model_config.toml` 里的哪个任务；留空用默认任务 |
| 温度 / 最大输出 token | 0 / 64 | 判定只输出编号，不需要长回复 |
| 判定冷却秒 | 30 | 同一会话两次判定的最小间隔 |
| 背景消息条数 | 6 | 判定时带上最近几条对话 |
| 最短判定长度 | 4 | 太短的消息不判定，省掉「嗯」「哦」这类调用 |

一次判定只调一次模型：把所有带「模型判定条件」的人格列成编号清单，让模型回编号。

### 指令

`/人格`（或 `/persona`）随时可查，返回当前生效的人格、剩余时间与各人格分数：

```
【人格状态】
当前：嘴臭人格（剩余 5 分 12 秒）
分数：
- 嘴臭人格：12.0/30
- 撒娇人格：4.0/24
（每分钟衰减 1.5 分；/人格 重置 可清零）
```

- `/人格 切换 <人格ID>`：手动切过去（维持时长按该人格配置）；
- `/人格 重置`：清零本会话分数并恢复原人格。

手动操作只允许本机操作者，或在「指令」配置节里加进「可操作用户 ID」的人。

## 默认两个人格

| ID | 名称 | 阈值 | 维持 | 主要触发 |
| --- | --- | --- | --- | --- |
| `sharp_tongue` | 嘴臭人格 | 30 | 8 分钟 | 骂人词（智障/废物/垃圾/滚…，+14）、轻怼词（笨/蠢/傻/菜/就这…，+6） |
| `sweet` | 撒娇人格 | 24 | 6 分钟 | 被夸被示好（可爱/好厉害/喜欢你…，+8，需 @ 麦麦）、道谢（+5，需 @ 麦麦） |

加一个人格就是加一行：填 ID、阈值、维持时长、三段设定文本，再在它的「触发规则」里加加分条件。

## 调参建议

- **想让切换更快**：降低阈值，或提高触发加分；也可以把「衰减宽限分钟」拉长一点，让分数容易堆起来。
- **想让临时人格待得更久**：加大「维持分钟」；想让它更容易掉回原人格就反过来。
- **怕误伤**：给触发规则打开「需要 @ 麦麦」，或把权重降下来并配合模型判定。
- **关键词是「包含」匹配**，会有误报：比如「傻瓜」「傻乎乎」也会命中「傻」。默认权重已经把这类词压得比较低，如果你觉得吵，直接把词删掉或改用正则模式。
- 调参时保持「记录加分日志」开着，日志里会写清是哪个人格、加了多少分、当前分数和触发内容。

## 数据与状态

- 分数状态落盘在宿主数据目录：`data/plugins/local.persona-switcher/persona_scores.json`，
  重启后分数和临时人格的剩余时间都在（写盘是「先写临时文件再替换」，断电不会写坏）。
- 插件配置就是插件目录下的 `config.toml`，改完保存即热生效。
- 最近对话缓存只放在内存里（给模型判定用），不落盘。

## 开发

```bash
# 插件逻辑自检：计分/衰减/冷却/切换/到期/提示词替换/指令/模型判定（41 项）
<MaiBot>/python-env/python.exe plugins/persona-switcher/tests/selfcheck.py

# 宿主侧校验：Manifest、插件加载、组件注册、WebUI 配置 Schema、Item 契约往返
cd <MaiBot> && python-env/python.exe plugins/persona-switcher/tools/host_check.py

# 配置模型改动后重新生成默认 config.toml
cd <MaiBot> && python-env/python.exe plugins/persona-switcher/tools/generate_default_config.py
```

## 边界与已知限制

- 只改写发给模型的提示词，不碰宿主配置，也不做「回复文本的事后改写」。如果同一轮里模型被别处的强约束拉回原风格，插件不会二次纠正。
- 只在有临时人格生效时改写请求；没有生效人格时插件完全是旁观者。
- 临时人格是「语气与人设」层面的替换。若某人格的设定文本为空，插件会跳过对应段落（设定空的字段不会清空原内容）。
- **本机实测到的一个环境现象**：这台 MaiBot 的第三方插件被两个 Runner 实例同时加载，同一条群消息会被派发两次（日志里能看到同一个 handler 隔一百毫秒跑两遍，别的插件也一样）。因此分数会按两倍速度累积——把阈值当成「两条消息才满」来调即可；要根治得在宿主侧避免重复加载同一批插件。
