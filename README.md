# mai is mortis（麦麦是多首的怪物）

**麦麦是多首的怪物。**

给麦麦装上一套会积累、会平复的脾气：加分全部由模型判定，分数满了临时换人格，维持一段时间后自动切回原人格，分数随时间衰减。

## 它做什么

- **模型判定加分**：每来一批消息，插件把最近几条对话交给模型判一次（一次调用判完所有条件），
  命中哪个人格的「判定条件」就给谁加分。不用写关键词和正则，条件就是一句话。
- **分数满即换人格**：某个人格分数顶到阈值就顶替掉主人格，其他人格分数清零；
  维持若干分钟后自动切回原人格。
- **分数会衰减**：最后一次加分后有一段免衰减宽限期，之后每分钟按配置速度回落。

改人格语气时只改这一次请求的提示词：人设与说话风格（`personality.personality` / `reply_style`）
按临时人格替换，规划器行为风格可选同步替换。**不写宿主的 `bot_config.toml`**，
所以到期自动恢复，你在 WebUI 改人设也会立刻生效。每个会话（群/私聊）各记一套分数。

## 安装

把 `mai-is-mortis` 目录放进 MaiBot 的 `plugins/` 下即可（宿主会热加载）。
依赖：MaiBot ≥ 1.0.0、插件 SDK ≥ 2.10.0，声明的能力为 `config.get`、`llm.generate`。

## 配置

全部在 WebUI 插件配置页里改，改完即生效。常调的几项：

| 配置节 | 字段 | 默认 | 说明 |
| --- | --- | --- | --- |
| 基础设置 | 详细日志 | 开 | 记录入站消息、判定原始输出、每次加分，调参时很有用 |
| 计分与衰减 | 每分钟衰减 / 衰减宽限分钟 | 1.5 / 1.5 | 分数回落速度与免衰减保护期 |
| 计分与衰减 | 分数上限 | 60 | 单人格分数上限，防一触发就爆表 |
| 切换行为 | 切换时清空分数 | 开 | 避免到点后又被同一批话立刻顶起来 |
| 切换行为 | 生效期间继续计分 | 关 | 关掉时临时人格生效期间不调模型，省 token |
| 模型判定 | 模型任务 | fast_model | 建议用快而便宜的小模型；留空的 fast_model 会回落到 utils |
| 模型判定 | 抖动等待秒 / 判定冷却秒 | 1.5 / 5 | 连发消息并成一次调用；两次判定的最小间隔 |
| 模型判定 | 背景消息条数 / 最短判定长度 | 8 / 2 | 判定带多少上文；太短的消息（「嗯」「？」、表情包占位）不判 |

「人格列表」是一张可编辑表格，一行就是一个头：

| 字段 | 说明 |
| --- | --- |
| 人格 ID / 人格名称 | ID 唯一，用于日志与 `/人格 切换` |
| 判定条件 | 一句话交给模型判断；写清「算什么」也写清「什么不算」 |
| 命中加分 / 切换阈值 | 命中一次加多少分；加到多少分就切过去 |
| 维持分钟 | 切过去后维持多久，到点自动切回原人格 |
| 人格设定 / 说话风格 / 规划行为风格 / 额外要求 | 要替换或追加的文本，留空表示该段保持原样 |

默认两个人格：

| ID | 名称 | 判定条件 | 加分 | 阈值 | 维持 |
| --- | --- | --- | --- | --- | --- |
| `sharp_tongue` | 嘴臭人格 | 对方在骂麦麦、阴阳怪气地嘲讽麦麦，或明显在挑衅、抬杠（普通玩笑不算） | +12 | 30 | 8 分钟 |
| `sweet` | 撒娇人格 | 对方在夸麦麦、向麦麦示好，或表达了喜欢、想念 | +10 | 24 | 6 分钟 |

## 指令

- `/人格`（或 `/persona`）：看当前生效的人格、剩余时间与各人格分数；
- `/人格 切换 <人格ID>`：手动切过去，到点照样自动切回；
- `/人格 重置`：清零本会话分数并恢复原人格。

后两条默认只允许本机操作者，或在「指令」配置节里填「可操作用户 ID」。

## 调参建议

- 想切换更快：降阈值、提高命中加分，或把「衰减宽限分钟」拉长；
- 想更省 token：把「判定冷却秒」调到 15~30、「抖动等待秒」调到 3、「最短判定长度」调大；
- 判定不准时先改「判定条件」那句话，比调分数有效得多；
- 调参时保持「详细日志」开着，日志里能看到模型这次回了什么编号、是谁加了分；**调完记得关掉**（它会记入站消息文本）。

## 开发

```bash
# 逻辑自检（评分、衰减、判定解析、切换、到期、提示词替换、指令、节流、损坏状态文件兜底）
python tests/selfcheck.py                 # 用宿主的 python-env 解释器运行

# 宿主侧校验（Manifest、组件注册、WebUI 配置 Schema、Item 契约往返）
cd <MaiBot> && python-env/python.exe plugins/mai-is-mortis/tools/host_check.py

# 改过配置模型后重新生成配置模板 config.toml.example
cd <MaiBot> && python-env/python.exe plugins/mai-is-mortis/tools/generate_default_config.py
```

仓库**不跟踪** `config.toml`：宿主首次加载插件时会按配置模型自动生成它，WebUI 保存配置也会重写它。
提交进版本库的是模板 `config.toml.example`，由上面那条命令从 `mortis/config.py` 的配置模型生成。
`tools/publish_github.py` 只是维护者用的发布脚本（宿主不会加载它）：它从 git 凭据库读 GitHub token、
只访问写死的 `api.github.com` 并校验解析出的 IP 为公网地址，代码里不含任何凭据。

## 已知限制

- 只改写发给模型的提示词，不做回复文本的事后改写；同一轮里若被别处的强约束拉回原风格，插件不会二次纠正。
- 没有临时人格生效时插件是彻底的旁观者；人格设定文本留空的字段不会清空原内容。
- 判定失败（模型报错、空回复）只记一条警告日志，不加分、不影响正常聊天。
- 两个 Runner 同时加载同一批第三方插件的宿主环境里，同一条消息会被派发两次；插件按会话做判定节流，
  重复派发通常被冷却吸收，但每次判定仍可能被调用两次（判定成本翻倍）。
