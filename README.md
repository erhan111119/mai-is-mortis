# 人格切换（模型判定打分）

给麦麦加一套「情绪积累 → 临时换人格 → 到点自动恢复」的机制。默认配置的效果：

- 插件把最近的对话交给模型判定：有人在骂麦麦 / 阴阳怪气地嘲讽麦麦 → **嘴臭人格**加分；有人夸麦麦、示好 → **撒娇人格**加分；
- 某个人格的分数顶到阈值 → 立刻切过去，**其他人格分数清零**；
- 该人格维持若干分钟后**自动切回原人格**；
- 分数随时间衰减：最后一次加分后的宽限期内不掉，之后按配置速度往下掉。

**不做关键词/正则匹配**：判断「这句算不算数」全部交给模型，条件用一句自然语言写清即可
（例如「对方在骂麦麦、阴阳怪气地嘲讽麦麦，或者明显在挑衅、抬杠」）。人格的判定条件、命中加分、
阈值、维持时长、衰减速度全部在 WebUI 里可改，不用碰代码。

## 它怎么改变麦麦的语气

插件**不改写宿主的 `bot_config.toml`**。它只在「这一次发给模型的请求」里做替换：

1. `chat.receive.after_process`：记录消息，按「抖动等待 + 判定冷却」节流地发起一次模型判定；
2. 模型按各人格的「判定条件」回编号 → 命中的人格按「命中加分」加分，分数满了就切换；
3. `maisaka.replyer.before_model_request`：临时人格生效时，把系统提示里的
   `{identity}`（人格设定）与 `{reply_style}`（说话风格）换成该人格的版本；
4. `maisaka.planner.before_request`：可选地同步改写规划器的行为风格（`{behavior_style}`）；
5. `maisaka.replyer.before_request`：把该人格的「额外要求」并进本次回复要求。

原人格文本是从宿主配置里读出来的（`personality.personality` / `reply_style` / `behavior_style`），
在提示词里定位到同一段文字后替换。因此：

- 临时人格到期后不需要「恢复」动作，下一次请求读到的仍然是配置里的原文；
- 你在 WebUI 里改人设会立刻反映到下一次回复；
- 不同会话（群 / 私聊）各记一套分数，一个群把麦麦骂急眼了，别的群不受影响。

## 安装

把整个 `persona-switcher` 目录放进 MaiBot 的 `plugins/` 下即可。宿主的插件目录监听会热加载它，日志里能看到：

```
插件 local.persona-switcher v2.0.0 加载成功
人格切换插件已加载：人格=嘴臭人格、撒娇人格；判定模型任务=fast_model；衰减 1.5 分/分钟（宽限 1.5 分钟）
```

之后在 WebUI 的插件配置页里就能看到「人格列表」表格，逐项调参。

## 配置说明

### 基础设置

| 字段 | 说明 |
| --- | --- |
| 启用插件 | 关掉后不再判定、不再加分，麦麦始终用原人格 |

### 计分与衰减

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| 每分钟衰减 | 1.5 | 宽限期结束后，每分钟掉多少分，掉到 0 为止 |
| 衰减宽限分钟 | 1.5 | 最后一次加分后的免衰减时间。宽限期内连续触发才能把分数堆上去 |
| 分数上限 | 60 | 单个人格分数上限，避免慢慢攒着、一触发就爆表；0 表示不限 |
| 最多会话数 | 200 | 最多记住多少个会话的分数，超出后淘汰最久未用的 |

### 切换行为

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| 切换时清空分数 | 开 | 切换时把所有人格（含刚切过去的这个）分数清零，避免到点后又立刻被同一批话顶起来 |
| 生效期间继续计分 | 关 | 默认生效期间暂停判定，让临时人格老老实实待够时间（也省 token） |
| 同步改写规划器 | 开 | 让人格配置里的「规划行为风格」也生效，影响「要不要回、怎么回」 |
| 落盘间隔秒 | 20 | 分数状态写盘的最小间隔，写盘是为了重启后分数和剩余时间还在 |
| 记录加分日志 | 开 | 每次加分写一条 INFO 日志，调阈值时对着日志看最直观 |
| 记录入站消息日志 | 开 | 每条入站消息写一条 DEBUG 日志（会话、长度、是否 @）。排查「插件到底看没看到消息」时用得上 |

### 模型判定（唯一的加分来源）

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| 启用模型判定 | 开 | 关掉后不会有任何加分（临时人格仍会正常到期恢复） |
| 模型任务 | fast_model | 用 `model_config.toml` 里的哪个任务来判定。建议用快而便宜的小模型：`fast_model` 或 `utils` |
| 温度 / 最大输出 token | 0 / 64 | 判定只输出编号，不需要长回复；温度保持 0 让结论稳定 |
| 抖动等待秒 | 1.5 | 收到消息后先等这么久再判定，把连着发的几条消息并成一次调用 |
| 判定冷却秒 | 5 | 同一个会话两次判定的最小间隔；冷却期内来的新消息会被记下，等冷却到了再补判一次 |
| 背景消息条数 | 8 | 判定时带上的最近对话条数（含最新一条） |
| 最短判定长度 | 2 | 太短的消息不判定，省掉「嗯」「？」，以及表情包/图片这类占位文本的调用 |
| 记录判定原始输出 | 开 | 把模型回复写进 DEBUG 日志，用来确认判定是否按预期工作 |

判定是**一次调用判完所有条件**：插件把所有参与判定的人格列成编号清单，模型只回命中的编号
（例如回 `1` 或 `1, 2`，都不满足回 `none`）。同一会话同一时刻只有一个判定在跑，
热聊时也不会每条消息都调一次模型。

### 指令

`/人格`（或 `/persona`）随时可查，返回当前生效的人格、剩余时间与各人格分数：

```
【人格状态】
当前：嘴臭人格（剩余 5 分 12 秒）
分数：
- 嘴臭人格：12.0/30
- 撒娇人格：4.0/24
（每分钟衰减 1.5 分；/人格 重置 可清零）
```

- `/人格 切换 <人格ID>`：手动切过去（维持时长按该人格配置）；
- `/人格 重置`：清零本会话分数并恢复原人格。

手动操作只允许本机操作者，或在「指令」配置节里加进「可操作用户 ID」的人。

### 人格列表（表格）

每一行是一个可切换的人格：

| 字段 | 说明 |
| --- | --- |
| 人格 ID / 人格名称 | ID 唯一，用于日志与 `/人格 切换`；名称用于展示 |
| 判定条件 | 一句话交给模型判断，例如「对方在骂麦麦、阴阳怪气地嘲讽麦麦，或者明显在挑衅、抬杠」。留空表示这个人格不参与自动切换 |
| 命中加分 | 模型判定命中一次加多少分 |
| 切换阈值 | 分数加到这么多就切过去；填 0 表示这个人格只手动用 |
| 维持分钟 | 切过去后维持多久，到点自动切回原人格 |
| 人格设定 | 替换 `personality.personality`。建议写清「这是个什么状态」+ 语气边界 |
| 规划行为风格 | 替换 `personality.behavior_style`，留空表示规划阶段保持原样 |
| 说话风格 | 替换 `personality.reply_style`，留空表示说话风格保持原样 |
| 额外要求 | 追加到本次回复要求里，用来强调「这次必须按临时人格说」 |

## 默认两个人格

| ID | 名称 | 判定条件（交给模型） | 命中加分 | 阈值 | 维持 |
| --- | --- | --- | --- | --- | --- |
| `sharp_tongue` | 嘴臭人格 | 对方在骂麦麦、阴阳怪气地嘲讽麦麦，或者明显在挑衅、抬杠；也包括拿麦麦当出气筒 | +12 | 30 | 8 分钟 |
| `sweet` | 撒娇人格 | 对方在夸麦麦、向麦麦示好，或者表达了喜欢、想念，语气明显是宠着麦麦的 | +10 | 24 | 6 分钟 |

加一个人格就是加一行：填 ID、判定条件、命中加分、阈值、维持时长和三段设定文本。

## 调参建议

- **想让切换更快**：降低阈值、提高命中加分，或把「衰减宽限分钟」拉长一点让分数容易堆起来。
- **想让临时人格待得更久**：加大「维持分钟」；想让它更容易掉回原人格就反过来。
- **判定太频繁 / 太贵**：把「判定冷却秒」调大（例如 15~30 秒）、「抖动等待秒」调大（例如 3 秒），
  或「最短判定长度」调大；模型任务换成更便宜的小模型（`fast_model` / `utils`）。
- **判定太保守/太激进**：改「判定条件」这句话本身最有效——写清「算什么」也写清「什么不算」
  （默认条件里就写了「普通的玩笑和吐槽不算」），必要时多写几句边界。
- 调参时保持「记录加分日志」与「记录判定原始输出」开着：日志里会写清是哪个人格加分、
  当前分数，以及模型这次到底回了什么编号。

## 数据与状态

- 分数状态落盘在宿主数据目录：`data/plugins/local.persona-switcher/persona_scores.json`，
  重启后分数和临时人格的剩余时间都在（写盘是「先写临时文件再替换」，断电不会写坏）。
- 插件配置就是插件目录下的 `config.toml`，改完保存即热生效。
- 最近对话缓存只放在内存里（给模型判定用），不落盘。

## 边界与已知限制

- 只改写发给模型的提示词，不碰宿主配置，也不做「回复文本的事后改写」。如果同一轮里模型被别处的强约束拉回原风格，插件不会二次纠正。
- 只在有临时人格生效时改写请求；没有生效人格时插件完全是旁观者。
- 临时人格是「语气与人设」层面的替换。若某人格的设定文本为空，插件会跳过对应段落（设定空的字段不会清空原内容）。
- 加分依赖模型判定，所以判定的准确度取决于「判定条件」写得清不清楚，以及所配模型任务的能力；判定失败（模型报错、空回复）只记一条警告日志，不加分、不影响正常聊天。
- **本机实测到的一个环境现象**：这台 MaiBot 的第三方插件被两个 Runner 实例同时加载，同一条群消息会被派发两次（日志里能看到同一个 handler 隔一百毫秒跑两遍，别的插件也一样）。插件按会话做判定节流，因此重复派发通常会被冷却吸收，不会把分数算两倍；要根治得在宿主侧避免重复加载同一批插件。
